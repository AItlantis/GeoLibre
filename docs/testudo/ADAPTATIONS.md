# Testudo bridge port adaptations

Source: `F:\repos\geolibre-testudo-v31`, commit `0ec6f90c` only. The port retains the AItlantis Testudo shell and the website's legacy guest protocol.

- Ported the embed DTO/client additions and generic feature session, bridge, camera validator, host protocol helpers, and their tests additively. Existing Testudo verbs remain available, including `testudoSetGuestCapability`, `testudoLoadPackage`, `testudoOpenLocalPackage`, `testudoSetPlugin`, `testudoSetMode`, `testudoOpenGeoAiChat`, `testudoRequestInvestigation`, `testudoSetPreset`, and `testudoGetState`.
- Kept the generic provider/session contracts, but the desktop host exposes one TView named `main`. Attempts to address another TView are rejected. Create/get/destroy are supported for `main`; destroy clears the package and recreates the empty view while preserving the generation sequence. A package load replaces that session and advances its generation; artifact, scenario, playback, camera, and GeoAI operations are fenced to it.
- Bound sessions to the original MapLibre plugins with thin playback/scenario adapters. Vehicle playback maps its tick, playing and speed settings. KPI-family, emissions and path playback map their native interval APIs to shell ordinal ticks. Scenario-pair updates call the existing comparison settings API. No renderer, panel, reader, or plugin implementation was copied or rewritten.
- Comparison capability is hidden while it is only declared. It is advertised after the original comparison plugin reports both timelines and matched intervals; a declared but unsupported comparison is not shown as available. Animation is advertised only when the original package scenario list contains playable scenarios, and selecting it chooses the first available scenario if none is selected.
- Signed-in published-package reads use credential-free artifact requests from the iframe to the embed host. The host's `fetchArtifact` callback keeps authentication in its own closure and returns bytes with request/TView/generation correlation. Signed-in GeoAI chat now relays bounded, credential-free turns through the feature bridge and requires the host's GeoAI request subscriber; replies are correlated by request/TView/generation. GeoAI buildings remain unavailable because no host route exists. The legacy guest capability command and guest-only package/chat transport remain for the website demo.
- Relay chat sends only the selected main plugin id, up to 11 transcript turns (2,000 characters each, 20,000 total), and allowlisted viewer context. `scenario_analysis` is bounded display data; validated scenario/viewer suggestions are shown as text and are never applied automatically. The existing guest `viewer_action` handling remains unchanged.
- `testudoOpenLocalPackage` now waits for an in-iframe translated folder-picker button before calling `showDirectoryPicker`, because parent `postMessage` does not preserve browser user activation. After selection, the same single `main` TView is replaced with a new generation and reads artifacts directly from the user's directory. Selected vehicle/path identifiers are omitted where the reused plugin APIs do not expose those selections; bounded counts, section selection, interval, time, and camera context are sent when available.
- Removed `bearerToken` from the Testudo package-load DTO and recursively reject credential-shaped fields in signed-in bridge payloads. Generic `createSignedPackageSource` still has a bearer option for non-Testudo callers, but `TestudoControls` never invokes that branch for a signed-in profile; it uses the parent-proxied source instead.
- Testudo readiness drops wildcard origins and posts only to exact configured parent origins selected with the parent-origin hint. The generic embed API's old wildcard pre-handshake behavior is unchanged for its other consumers.
- Preserved `selectMode("animation")` first-scenario selection and clear stale viewer error state after a failed command that leaves the package loaded.
- Added a Testudo-only persistent network mount. It reuses the original network-KPI geometry loader, draws the sections/lanes/turns/nodes once under bridge ownership, fences asynchronous geometry reads by package generation, and keeps the neutral network through mode changes. In the Testudo layout, network-KPI omits its neutral base deck layer, vehicle playback skips its plugin-owned network, and path analysis skips its duplicate section base; their existing overlays and readers remain in use.
- Kept one network-KPI `ParquetResultsDatabase` instance for the active package/generation. Testudo mode teardown leaves that package-scoped instance alive; replacing/clearing the package disposes its registered Parquet files. Comparison and emissions continue using the same shared DuckDB-WASM database runtime through the existing dataset provider.
- Classified vehicle playback's gzipped chunk reader as a non-DuckDB registry family member. It remains tracked for cleanup but does not consume or evict the DuckDB plugin family's concurrency slot.
- Made path analysis accept the selected scenario id and resolve `path_indices` / `pathIndicesByScid` by that id. The Testudo bridge exposes package scenarios to path mode, selects the first scenario on entry, and routes later scenario changes through the existing path loader. Singular `path_index` and prior path-analysis calls remain supported.
- Added focused ownership tests for mount-once behavior, generation fencing, per-generation results-resource reuse, and DuckDB-family eviction.
- Extended the Testudo mode bridge additively to accept the shell ids `results`, `comparison`, `environment`, `animation`, and `paths`, while retaining legacy `flow` and `density`. Results, comparison, and environment still select the original network-KPI, scenario-comparison, and emissions plugins over the persistent network; animation and paths continue to use their original overlays. Mode availability is derived from package declarations and checked against comparison matched intervals and the emissions plugin's `hasEmissions` status; unavailable selections return a reason.
- Added generation-fenced `testudoSetStyle` and scenario selection state updates. Style changes call the original plugin settings APIs and validate the display, metric, interval, height, and comparison scenario indexes. Viewer state carries package `viewModes`, `timeAxis`, the active style, scenario roster, selected scenario, and selected mode for the shell header and legend.
- `parseGeolibrePackage` now retains validated `results.viewModes` and `results.timeAxis`, including alternates and scenario/did pairs. The bridge uses the declared metric and ramp/extrusion defaults when selecting a view.
- Comparison and emissions now share one generation-scoped `TestudoDatasetProvider` (and the existing shared DuckDB-WASM runtime) with network KPI results. Plugin deactivation releases its view; replacing or clearing the package generation closes the shared provider and the package-scoped `ParquetResultsDatabase`.
- Fixed the network-KPI Parquet timeline lookup for per-did SIM_INFO catalogs: it now queries all registered SIM_INFO partitions instead of only the first file. The london-v3 package data is correctly partitioned by did; this was a plugin query bug, not a package-builder defect.
- Added focused tests for shell/legacy mode mapping and availability, style validation, package view-mode/time-axis exposure, per-generation provider/database reuse, and multi-partition SIM_INFO lookup.
- P2 step 6c restores the shell's typed client commands and iframe handlers additively. KPI geometry visibility is owned by the existing persistent network service and remains generation scoped; legend visibility uses the original legend control; Esri imagery is a persistent bridge-owned raster layer. Renderer changes use the existing app store. Annotation, recording, and network-filter calls fail with explicit unavailable-capability errors where this iframe has no corresponding original plugin control. Unknown command names are acknowledged as unsupported instead of being interpreted as presets; existing preset and legacy guest verbs remain intact.
- Metric validation accepts package column aliases (`dtime`/`nstops`) and maps comparison scenario ids to the original comparison plugin's zero-based indexes. Unchecking the shell's comparison difference control clears its pair and selects the plugin's side-by-side mode; active difference values retain the plugin's Compared-minus-Reference (B-A) convention.
- The iframe forwards generation-fenced playback updates from the selected plugin adapter as `testudoPlaybackChanged`, and initializes the active mode's playback state after mode selection. Environment availability is recomputed on scenario changes, published in viewer state, and falls back to an available mode while retaining Environment as the preferred mode for restoration.

Still outside this port: multi-TView rendering, GeoAI Buildings host routes, and artifact-fetch host implementations in embedding applications that do not provide `fetchArtifact`. Steps 4, 5, and P2 step 6a are included here.
