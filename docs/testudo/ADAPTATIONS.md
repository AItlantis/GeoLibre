# Testudo bridge port adaptations

Source: `F:\repos\geolibre-testudo-v31`, commit `0ec6f90c` only. The port retains the AItlantis Testudo shell and the website's legacy guest protocol.

- Ported the embed DTO/client additions and generic feature session, bridge, camera validator, host protocol helpers, and their tests additively. Existing Testudo verbs remain available, including `testudoSetGuestCapability`, `testudoLoadPackage`, `testudoOpenLocalPackage`, `testudoSetPlugin`, `testudoSetMode`, `testudoOpenGeoAiChat`, `testudoRequestInvestigation`, `testudoSetPreset`, and `testudoGetState`.
- Kept the generic provider/session contracts, but the desktop host exposes one TView named `main`. Attempts to address another TView are rejected. Create/get/destroy are supported for `main`; destroy clears the package and recreates the empty view while preserving the generation sequence. A package load replaces that session and advances its generation; artifact, scenario, playback, camera, and GeoAI operations are fenced to it.
- Bound sessions to the original MapLibre plugins with thin playback/scenario adapters. Vehicle playback maps its tick, playing and speed settings. KPI-family, emissions and path playback map their native interval APIs to shell ordinal ticks. Scenario-pair updates call the existing comparison settings API. No renderer, panel, reader, or plugin implementation was copied or rewritten.
- Comparison capability is hidden while it is only declared. It is advertised after the original comparison plugin reports both timelines and matched intervals; a declared but unsupported comparison is not shown as available. Animation is advertised only when the original package scenario list contains playable scenarios, and selecting it chooses the first available scenario if none is selected.
- Signed-in published-package reads use credential-free artifact requests from the iframe to the embed host. The host's `fetchArtifact` callback keeps authentication in its own closure and returns bytes with request/TView/generation correlation. Signed-in GeoAI chat and GeoAI buildings are marked unavailable because this port does not add a host-authenticated AI route. The legacy guest capability command and guest-only package/chat transport remain for the website demo.
- Removed `bearerToken` from the Testudo package-load DTO and recursively reject credential-shaped fields in signed-in bridge payloads. Generic `createSignedPackageSource` still has a bearer option for non-Testudo callers, but `TestudoControls` never invokes that branch for a signed-in profile; it uses the parent-proxied source instead.
- Testudo readiness drops wildcard origins and posts only to exact configured parent origins selected with the parent-origin hint. The generic embed API's old wildcard pre-handshake behavior is unchanged for its other consumers.
- Preserved `selectMode("animation")` first-scenario selection and clear stale viewer error state after a failed command that leaves the package loaded.

Still outside this port: multi-TView rendering, signed-in GeoAI/GeoAI Buildings host routes, and artifact-fetch host implementations in embedding applications that do not provide `fetchArtifact`. The port ends at step 3; steps 4–6 are not included.
